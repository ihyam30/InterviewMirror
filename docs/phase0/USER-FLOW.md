# 用户流程与失败路径

> 版本：`interviewmirror.user-flow.v1.0.0`  
> 状态：Stage 0 需求基线。在线/服务端实现尚未开始；流程基于仓库 Demo 与根目录 `DEVELOPMENT_PLAN.md`。

## 1. 角色与入口

唯一首版角色是求职者。用户进入本地演示后，从工作台到“模拟面试 / 历史报告 / 自定义题库 / 我的简历”。公开注册、邮箱验证和多租户协作不在首版范围。服务端仍按本地账号校验资源所有权。

### 登录

1. 用户打开本地地址，输入初始化演示账号与密码。
2. 登录成功后进入工作台；账号未初始化或密码错误时显示可理解错误，不泄漏账号是否存在。
3. 用户退出后本地会话失效；重新登录后只能读取本人简历、题库、面试和报告。

| 情况 | 行为 |
|---|---|
| 初次运行没有账号 | 按 README 的本地初始化命令创建演示账号；不提供公网注册 |
| 密码错误/账号被停用 | 拒绝登录、限制短时间重复尝试、记录不含密码的安全事件 |
| 会话过期 | 保留服务端已保存回答；返回登录页，登录后恢复未结束场次 |
| Demo 当前行为 | Demo 没有登录页；展示预置“林同学”，数据由 `localStorage` 隔离在当前浏览器，不代表后端权限实现 |

## 2. 我的简历

1. 用户从导航打开“我的简历”，可查看、设为默认、上传或删除。
2. 上传 PDF/DOCX；检查 MIME、扩展名、20 MB 上限和 PDF 页数（最多 50 页）。超限/格式不符在解析前拒绝。
3. 新文件进入 `QUEUED → PROCESSING`。解析器失败进入 `FAILED` 并说明可重试原因。
4. 成功解析进入 `REVIEW_REQUIRED`。展示姓名、教育、技能、项目、结果等字段及页码/段落来源；用户可编辑和确认。
5. 确认后为 `READY`，才能用于综合面试。未经确认的资料不可进入模型上下文。
6. 用户可删除简历；删除时清除原文件、解析结果、索引/缓存和该资料引用的检查点数据。已完成报告保留脱敏后的必要证据快照或按用户选择级联删除，规则需在产品中明确。

失败与边界：空白文档、加密 PDF、损坏 DOCX、OCR 扫描件不可读、字段抽取为空均进入 `REVIEW_REQUIRED` 或 `FAILED`，不得伪造 `READY`。可以重试；人工编辑仍需用户确认。

## 3. 自定义题库

1. 用户进入“自定义题库”，上传 PDF/DOCX/TXT/Markdown，或手动创建题库。
2. 文件限制与安全扫描同简历；纯文本直接读取，结构化 PDF/Office 走本地 MinerU。
3. 解析题干、分组和编号并保留文件页码/段落来源，状态流转同简历。
4. 用户可编辑、删除、补充题目，至少保留 1 道有效问题后确认。
5. 已确认题库可从题库卡片或专项面试配置页选择；题库删除后不可用于新场次。

失败与边界：无法抽取题目、重复题、只有标题没有题干、问题编号断裂时提示修正；不能以空题库开始。模型提示注入文本按不可信资料处理，不执行其中指令。

## 4. 综合面试

1. 从工作台/导航打开“模拟面试”，选择“综合面试”。
2. 选择一份 `READY` 简历（必选），粘贴 JD（可选；最多 1,500 字的 Demo 限制需在 API 版本锁定）。
3. 创建前校验简历归属、确认状态；没有可用简历时禁用开始并提供上传入口。
4. 建立场次快照，按简历项目和可选 JD 生成 5–8 个主问题，一次只展示一个问题。
5. 用户回答后评估回答证据、问题覆盖和追问必要性；每主问题最多追问 2 次。用户可主动结束；网络中断时先落库回答，重连后恢复。
6. 达到问题上限/用户提前结束后生成报告。只有同时满足 `mode=COMPREHENSIVE` 且 `jdText` 非空时生成差异分析摘要和完整分析；缺 JD 时显示“不适用”，绝不推断岗位匹配。

失败与边界：未确认简历、超限 JD、资料被删除/失权、模型超时或 JSON 校验失败时不继续消耗后续模型请求；已有逐轮回答保留，报告状态可重试。

## 5. 专项面试

1. 选择“专项面试”，必须选择一份 `READY` 自定义题库。
2. 服务端只加载题库快照和本场回答，不加载简历或 JD；请求若同时携带简历/JD，应拒绝，避免误用个人数据。
3. 从题库中抽取 5–8 个主问题；抽题策略记录题目 ID，避免重复；用户逐题回答，按规则追问。
4. 结束后生成通用能力复盘；岗位匹配和差异分析标为 `NOT_APPLICABLE`。

失败与边界：没有已确认题库或题库没有有效题目时拒绝开始；题库在创建后被删除时场次继续使用已确认快照，但后续重新面试需要重新选择仍有效题库。

## 6. 历史报告

1. 用户打开历史报告列表，按日期查看模式、岗位/题库标题、综合表现和（适用时）岗位匹配度。
2. 点选一条报告，查看基础信息、总体评价、维度评分、逐题反馈、优势、风险、改进建议和学习路径。
3. 适用差异分析的综合场次在报告中显示岗位匹配度、Top 3 差距、差距雷达图、一句话结论和“查看完整分析”。
4. 点击入口进入独立差异分析页，查看简历 vs JD、实际表现 vs 要求、归因、证据和优先级；返回按钮回到同一报告。
5. 下一步：重新面试以原模式与资料创建新场次、不覆盖旧报告；导出含 AI 生成标识的 PDF；返回主页不删除报告。

失败与边界：差异分析缺失时显示“不适用/未评估”原因；证据引用失效时隐藏结论并标记需重算；PDF 生成失败可重试，不修改报告。

## 7. Demo 与需求基线差异

| 项目 | Demo 当前行为 | Stage 0 / 计划基线 |
|---|---|---|
| 登录 | 无登录页，静态用户 | 本地预置账号，后端资源归属校验 |
| 简历/题库上传 | 浏览器选文件，展示静态模拟解析字段；原文件不上传 | MinerU 本地解析、异步状态、来源定位、用户确认 |
| 面试与追问 | 固定问题脚本；短回答触发一次追问；生成报告套用样例 | LangGraph4j 条件流程，5–8 主问题，每题最多 2 次追问，回答落库与恢复 |
| 报告评分 | Demo 样例为五维且含静态结果 | `DEVELOPMENT_PLAN.md` 当前五维基线；此阶段扩展七维合同草案，须按 `SCORING-RUBRIC.md` 映射 |
| 差异分析 | 页面/雷达数据为固定样例，入口是客户端视图切换 | 按简历、JD、回答证据生成并校验；只对综合 + JD 触发 |
| 持久化 | 当前浏览器 `localStorage` | PostgreSQL/MinIO 本地数据卷；删除与所有权检查 |
| AI 调用 | 无模型 API 调用 | Spring AI 候选比较，必须测量实际质量/Token/耗时 |

## 8. 端到端验收场景

1. 空简历库 → 上传 DOCX → 修正解析 → 确认 → 综合面试（无 JD）→ 报告显示差异“不适用”。
2. 综合面试有 JD → 报告展示摘要 → 打开完整分析 → 每条差距定位到 JD/简历/回答证据。
3. 上传 Markdown 题库 → 删除一题、补一题、确认 → 专项面试 → 请求/报告均无简历 ID、JD 和差异分析。
4. 综合面试缺简历、专项面试缺题库、用户无权访问资料：均在模型调用前拒绝。
5. 面试回答已保存后模拟断连/进程恢复；检查点恢复后下一节点正确，回答不重复、不丢失。
6. 模型超时/返回非法结构/引用不在来源中：有限重试一次；失败可重试报告但保留历史回答。

> 与 Demo 交互说明一致的既有决策：综合简历必选、JD 可选；专项题库必选且不关联简历；差异分析只在综合 + JD；报告可重新面试/导出/返回主页。
