# 岗位差异分析

> 历史设计文档：岗位差异分析已从当前产品停用。此文档仅记录旧版契约，不代表当前界面、API、Worker 或 PDF 行为。

## 生成门槛

仅当面试来源为 `COMPREHENSIVE` 且面试创建时的 JD 非空时生成。题库专项和无 JD 的综合面试必须为 `NOT_APPLICABLE`；后端详情与 retry API 再次验证门槛，不能由前端参数绕过。

## 逐项判断

模型把 JD 拆成最多 20 项要求，并标注 `CORE`、`IMPORTANT` 或 `PREFERRED`。服务端要求每项至少包含合法 JD 证据。简历/回答分数只有在引用相应 `RESUME` / `TURN` 证据时才会保留；否则清空该来源分数。

面试评分状态按已验证的面试分数解释：4–5 为 `MATCH`，3 为 `PARTIAL_GAP`，1–2 为 `GAP`；没有回答证据或分数时为 `NOT_EVALUATED`。未评估项在差距摘要中不得带证据或归因，不计入差距 top 3 和匹配度。评分以外的语义判断仍依赖模型，评测中固定检查引用来源和缺证据的安全行为。

要求重要度权重：CORE=3，IMPORTANT=2，PREFERRED=1。匹配度采用 0–5 分的加权均值转换为 0–100；简历/面试都有证据时按 40/60 组合，只有一个来源有证据时对该来源重新归一化。coverage 同时返回已评估要求数和要求总数。

雷达轴：技能、项目经验、问题解决、岗位职责。要求按固定关键词规则归类，各轴汇总可用来源分数；没有可评估要求的轴显示空值，而不是零分或默认满分。

## 页面与重试

报告详情页展示差异摘要、匹配度和状态；完整差异页列出 JD 要求、简历/面试证据、状态、原因和建议。模型失败不会破坏主报告，可以通过独立 gap retry API 重试。跨用户报告 ID 返回不可见，不泄漏是否存在。
