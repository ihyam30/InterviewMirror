# 阶段 4：面试报告与 PDF

> 当前状态更新（2026-10-05）：岗位差异分析已从产品中取消。本文关于差异分析的内容仅记录历史实现；当前前端不展示该功能，Worker 不创建或领取其任务，旧版详情/重试接口返回 `410 Gone`，PDF 不再包含差异分析。

## 范围

阶段 4 在阶段 3 的已完成面试上生成持久化复盘报告。报告读取创建面试时保存的来源快照和已回答 turn，不读取用户后来修改的简历或题库。模型输出只作为候选结果，服务端会重新计算汇总分数、适用状态和证据引用后再保存。岗位差异分析已经从产品中取消；旧版 Schema 仅保留作历史记录。

## 已实现能力

- 面试进入 `COMPLETE` 后创建报告任务；即使任务创建瞬间失败，worker 也会扫描已完成但缺少任务的面试并补建。
- PostgreSQL 保存任务状态、租约、尝试次数、重试次数、耗时、错误码和安全的用户可读错误。过期 `PROCESSING` 任务会回到可领取状态。
- 六维评分：技术深度、项目经验、岗位匹配、沟通表达、逻辑结构、问题解决。证据不足时保留 `UNASSESSED` 或 `NOT_APPLICABLE`，不会由模型给出的总分覆盖服务端评分。
- 每个回答 turn 的反馈必须引用该 turn 自身的回答证据；报告其他主要结论必须引用可验证的简历或回答证据。
- 报告保留总体评价，不再生成或展示“一句话结论”；总体评价会单独运行证据核验，不受支持或核验不可用时回退为原始回答摘录。
- 报告历史、详情、六维评分雷达图、独立重试、重新面试、主页最近报告和 PDF 导出已接入前端。
- PDF 在服务端生成中文可读、多页文档及六维雷达图，存放在私有对象存储。下载始终通过当前用户和报告 ID 授权校验。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/interviews/{id}/report-status` | 查询报告状态 |
| POST | `/api/v1/interviews/{id}/reports` | 幂等地请求/确保报告任务 |
| POST | `/api/v1/interviews/{id}/reports/retry` | 重试失败的报告任务 |
| DELETE | `/api/v1/interviews/{id}/report` | 删除当前用户本场面试、报告、问答记录及关联 PDF |
| GET | `/api/v1/reports` | 当前用户的报告历史 |
| GET | `/api/v1/reports/{id}` | 报告详情及原始来源快照 |
| GET | `/api/v1/reports/{id}/pdf` | 生成或读取当前用户的 PDF |

所有报告、任务和 PDF 查询在 repository 层带 `owner_id` 条件。未授权和不存在的资源统一按不可见处理。

删除报告前会先清理私有对象存储中的 PDF；对象删除失败时保留数据库记录并返回失败。题库专项报告不展示项目经验和岗位匹配维度，PDF 缓存版本同步失效重建。

## 当前实现边界

模型调用使用已有的 Spring AI OpenAI-compatible 配置；未配置时，面试记录仍保留，报告任务进入失败并可重试。阶段 4 评测数据只包含合成面试，不代表真实简历或真实面试上的语义质量。人工盲评、生产规模容量和 GitHub 托管 Runner 真实模型调用需要单独完成。
